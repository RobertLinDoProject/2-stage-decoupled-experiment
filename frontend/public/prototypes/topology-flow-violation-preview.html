為什麼要這樣比較？

如果兩邊使用不同場景，結果差異可能來自人口分布、拓樸難度或容量不同，而不一定是 Perception 造成的。因此本頁固定相同的 topology、capacity、scenario ground truth、Perception model、density regime、trial、M6 interface 與 M7 驗證標準，讓兩個分支可以直接比較。

不使用二階段框架M6 直接使用正確人口數（scenario_gt），作為理想參考。
使用二階段框架M6 只能使用 Perception 產生的觀測人口（observed_population），M7 仍使用同一份 scenario_gt 驗證。

這個違規規則代表什麼？
  • CAPACITY_CONSTRAINT：M7 的 post-population 超過該節點 capacity。
  • TOPOLOGY_CONNECTIVITY：source → target 不符合 topology allowed edge 或 destination rule。
  • SOURCE_UNDERFLOW：移出的人數超過 M7 所使用真值中的可用 source population。
  • FLOW_CONSERVATION：incoming / outgoing 流量不符合守恆規則。
  • UNKNOWN_ZONE：action 使用 topology 不存在的節點。
  • PARSE_ERROR：action 缺少必要欄位或無法解析。
  • UNKNOWN_RULE_CODE：M7 回傳尚未建立 UI 對應名稱的正式 reason，保留原始 code。

正式預覽只讀取 M3–M7 artifact；本頁不修改 topology、actions、validation evidence 或正式報告。
